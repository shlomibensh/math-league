# ליגת המספרים – גרסה עצמאית (GitHub Pages + Supabase)

אותו משחק כמו ב-Claude, עם סנכרון בין מכשירים לכל מי שמשחק – בלי חשבון.
כל שחקן מקבל **קוד שחקן** אקראי (למשל `K7QM-2XRA-9TPD`) ו**קישור אישי**. פותחים את הקישור במכשיר אחר וממשיכים מאותה נקודה.

| קובץ | מה הוא |
|---|---|
| `index.html` | המשחק |
| `config.js` | כתובת ומפתח של Supabase – **הקובץ היחיד שעורכים** |
| `schema.sql` | הטבלה והפונקציות ב-Supabase (מריצים פעם אחת) |
| `manifest.webmanifest`, `icon-*.png`, `apple-touch-icon.png` | אייקון והתנהגות של אפליקציה כשמוסיפים למסך הבית |
| `.github/workflows/keepalive.yml` | שומר על Supabase ער (ראו שלב 4) |
| `deploy.sh` | העלאה ל-GitHub Pages בפקודה אחת (ראו שלב 2) |

## 1. Supabase
1. ב-[supabase.com](https://supabase.com) פותחים פרויקט חדש בתוכנית החינמית. אזור קרוב לישראל, למשל Frankfurt.
2. **SQL Editor → New query**, מדביקים את כל `schema.sql` ולוחצים **Run**. אמורה להופיע הודעת Success.
3. לוחצים **Connect** בראש הפרויקט (או **Settings → API Keys**) ומעתיקים שני ערכים:
   - **Project URL** – נראה כמו `https://abcdefghijkl.supabase.co`
   - **Publishable key** – מתחיל ב-`sb_publishable_`. (מפתח anon ישן שמתחיל ב-`eyJ` עובד גם הוא.)
4. מכניסים את שניהם ל-`config.js`.

> המפתח ה-publishable נועד להיות גלוי בדף, וזה בטוח כאן: הטבלה סגורה לגמרי, והדף יכול רק לקרוא ולשמור שחקן לפי הקוד שלו. **לעולם לא מכניסים ל-`config.js` את ה-secret key.**

## 2. GitHub Pages

### הדרך המהירה – פקודה אחת
צריך [GitHub CLI](https://cli.github.com) (`brew install gh` במק). בטרמינל:
```bash
cd ~/Downloads
unzip math-league-site.zip -d math-league-site
cd math-league-site
bash deploy.sh
```
הסקריפט מעלה רק את קבצי המשחק, ומסרב לרוץ מחוץ לתיקייה הזו.
הסקריפט מתחבר ל-GitHub (בפעם הראשונה נפתח דפדפן לאישור), יוצר רפו ציבורי `math-league`, מעלה את כל הקבצים, מפעיל Pages, מגדיר את הסודות של ה-keepalive ומריץ אותו פעם ראשונה. בסוף הוא מדפיס את כתובת האתר. אם הרפו כבר קיים, הסקריפט עוצר ולא דורס כלום.
אם `config.js` מלא, אין צורך בשלבים 4 ו-5 שלמטה – הסקריפט עושה גם אותם.

### הדרך הידנית
1. ב-GitHub: **New repository**, מסמנים **Public**, ונותנים שם, למשל `math-league`.
2. **Add file → Upload files** וגוררים את כל הקבצים מהתיקייה (בלי תיקיית `.github` – היא בשלב 4).
3. **Settings → Pages → Build and deployment**: Source = **Deploy from a branch**, Branch = **main**, תיקייה **/(root)**, ואז **Save**.
4. אחרי דקה-שתיים האתר עולה בכתובת `https://USERNAME.github.io/math-league/`.

## 3. בדיקה
פותחים את האתר ומקלידים שם. בתחתית המסך צריך להופיע **"✓ ההתקדמות נשמרת בשרת"**.
ב-Supabase, ב-**Table Editor → league_progress**, תופיע שורה עם קוד השחקן.
אם מופיע "אין חיבור לשרת" – בדקו שוב את שני הערכים ב-`config.js`.

## 4. שמירה מהשהיה – חשוב
פרויקט Supabase חינמי **נכנס להשהיה אחרי 7 ימים בלי פעילות** (למשל בחופש). אחרי השהיה המשחק ממשיך לעבוד עם שמירה במכשיר, אבל הסנכרון מפסיק עד שמחזירים את הפרויקט ידנית מהדשבורד.
כדי למנוע את זה, הפעולה `keepalive.yml` פונה לפרויקט פעמיים בשבוע:
1. ברפו: **Add file → Create new file**, בשם `.github/workflows/keepalive.yml`, ומדביקים את תוכן הקובץ.
2. **Settings → Secrets and variables → Actions → New repository secret** – יוצרים שני סודות: `SUPABASE_URL` ו-`SUPABASE_KEY` (אותם ערכים כמו ב-`config.js`).
3. בדיקה: **Actions → supabase-keepalive → Run workflow**. צריך לראות וי ירוק.

GitHub משבית פעולות מתוזמנות ברפו ציבורי שלא היו בו שינויים 60 יום, ושולח על כך מייל. כשזה קורה, מפעילים מחדש בלחיצה מהמייל או מלשונית Actions.

## איך זה עובד, ופרטיות
- **הקוד הוא המפתח.** 12 תווים אקראיים (60 ביט), אז אי אפשר לנחש קוד של ילד אחר. מי שיש לו את הקוד או הקישור האישי יכול לראות ולשנות את ההתקדמות של אותו שחקן, ולכן כדאי להתייחס אליו כמו לסיסמה קלה.
- **מה נשמר:** כינוי, גביעים, סטטיסטיקות ויומן אימונים. אין מייל ואין שם משפחה – המשחק מבקש שם פרטי או כינוי.
- **אין רשימת שחקנים.** הטבלה לא נגישה מבחוץ, וגם לא ניתן לקבל ממנה רשימה.
- **גבולות:** כל מי שפותח את הדף יכול ליצור שחקן חדש. כל שחקן מוגבל ל-64KB (בפועל כ-10KB). בסוף `schema.sql` יש שורה אופציונלית שמנקה שחקנים שלא שיחקו שנה.
- **כמה מכשירים במקביל:** כל שמירה קוראת קודם מה שמכשירים אחרים שמרו וממזגת. כשחוזרים לאפליקציה שהייתה ברקע, היא מתעדכנת. איפוס במכשיר אחד מתפשט לכולם.
- **בלי אינטרנט:** ממשיכים לשחק, וההתקדמות נשלחת כשהחיבור חוזר.

## עדכון המשחק בעתיד
מחליפים רק את `index.html`. הקובץ `config.js` נשאר כמו שהוא.

## בלי Supabase
אם משאירים את `config.js` ריק, המשחק עובד עם זיכרון בדפדפן בלבד וכפתור "קוד התקדמות" להעברה ידנית – בדיוק כמו העותק הציבורי ב-Claude.
